# 架构与扩展边界

```text
文件 / ZIP / 官网采集
        ↓
package_import.py：统一资料记录（内容、归属、来源、错误）
        ↓
web/auto-package.mjs：用途、上下文、适用范围
        ↓
web/package.mjs：聚合岗位、绑定本次资料和规则、缓存求值
        ├── web/rules.mjs：学历、学位、身份、经历等基础判断
        ├── web/major-match.mjs：专业匹配分派及广东兼容策略
        │        └── web/major-policy.mjs：显式目录关系、名单、精确匹配
        └── web/document-rules.mjs：有适用范围的共性条款
        ↓
证据展示 / 结果筛选 / 岗位 PK / CSV
```

## 专业匹配

岗位规则与专业目录关系独立。`rules.mjs` 不再内嵌广东代码判断；`major-match.mjs` 优先使用本次考试的结构化专业规则，否则才选择广东兼容策略。其他地区没有适用规则时不套广东前缀，不把名称相似当作通过。

结构化规则的节点区分类别和具体专业，关系可以有多个父类别；层级策略允许传递，枚举策略只允许类别直接收录专业，精确策略不允许关系扩展。校验拒绝循环、跨学历关系、重复标识、缺少证据及未绑定考试范围的规则。

`package.mjs` 只编译已应用且适用于当前岗位的目录规则，并复查规则本身的省份/年度/考试类型，不能通过修改文件外层归属覆盖内层规则范围。多份规则冲突时返回待核对，不静默选时间较新的文件。专业规则与原始文档随资料包一起备份，恢复时再次校验。

匹配结果包括 `state`、`reason`、`matched`，显式规则命中还包含来源链接、考试上下文及关系路径原文。既有 UI 字段 `majorCodeHit` 为兼容名称，现表示确定的专业规则命中。岗位附件匹配与完整资格覆盖仍分开记录。

## 采集与资格分离

`collector.py` 负责公开网页、附件、校验与版本，`source_catalog.json` 是导航来源目录，`material_catalog.json` 是固定资料清单。下载成功不说明规则完整，也不代表考生可报考。
