# 让 AI 帮你部署到本地

适用于能读写本机文件、运行终端命令的 AI 助手，例如带本机操作权限的编码助手。只有普通网页聊天权限的 AI 可以解释命令，但不能替你安装或启动。是否能自动完成，也取决于系统权限、Python 和网络是否可用。

把下面整段复制给 AI。仓库私有时，需先由你在正常登录流程中取得访问权限，或自行下载 ZIP；不要把账号密码、令牌发进聊天。

## 可直接复制的指令

```text
请把“选职 · 公考资料包分析器”安装到我自己的电脑并启动，直到我能在浏览器中使用。

仓库：https://github.com/ai418033672-svg/gongkao-analyzer
目标：本机使用，不部署到公网，不修改业务功能。

请直接完成你有权限执行的步骤；遇到登录、系统安装权限或无法联网等真实阻塞时，说明具体原因及需要我完成的一步。不要把只提供命令当作已经安装成功。

1. 检查操作系统、Python 版本，以及本机是否已有这个项目。如果已有，先查看项目说明和本地修改，复用现有目录；不要覆盖用户文件、删除 data/、重置仓库或强行更新。需要下载时，克隆仓库，或使用用户已下载并解压的 ZIP。不要要求用户提供 GitHub 密码或令牌。
2. 阅读 README.md、docs/quick-start.md 和 requirements.txt。项目需要 Python 3.9+；使用项目不需要 Node、npm、数据库、AI API 或密钥。缺少 Python 时说明该系统的安装方法，由用户处理必要的系统权限，再继续。
3. 在项目根目录创建 .venv。如果已有虚拟环境，先确认它能运行且 Python 版本满足要求。用这个环境的 Python 安装 requirements.txt 中的依赖，不使用 sudo pip 或全局安装，不擅自升级依赖版本，也不关闭证书校验。
   Mac/Linux：python3 -m venv .venv，然后 .venv/bin/python -m pip install -r requirements.txt
   Windows：py -3 -m venv .venv，然后 .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   Windows 没有 py 但 python 版本符合时，可以用 python -m venv .venv。
4. 用同一个环境的 Python 运行 server.py --open。保留服务进程，让用户在你回复之后仍能访问。服务器只应监听 127.0.0.1；使用程序实际打印的端口。默认端口都被占用时改用 --port，不终止无关进程。
5. 实际检查本机首页能打开，HTTP 请求成功，页面包含“选职”“职位筛选”“公告采集”。如果能操作浏览器，展开“资料与自动识别结果”，点击“载入演示职位表”，确认职位清单出现可用行，并能打开某个岗位的“查看依据”。干净安装应使用虚构演示；已有本机真实样本时不要改动样本。不要为了验证而自动下载真实招考文件。
6. 没有浏览器操作权限时，至少验证 HTTP 首页和静态资源可访问，并明确告诉我演示交互仍需手动验收；不要声称已经验证了页面按钮。联网下载失败或模块缺失时，不要报告部署成功。
7. 最后告诉我：项目所在目录、实际访问地址、服务如何保持运行、怎样停止（Ctrl+C）和下次启动的完整命令。指向 docs/quick-start.md，并提示刷新或关闭页面前“保存资料包”，下次用“恢复资料包”。Windows 未经本项目真机验收，不要声称跨平台已全面验证。

完成标准：依赖安装成功；本机页面可访问；服务仍在运行；明确列出已验证的操作和剩余待人工检查项。不要公开数据，不上传个人档案或真实资料，不改变仓库可见性。
```

## 你需要提供什么

通常只需要允许 AI 访问项目目录和终端。若仓库无法下载，可以自己下载 ZIP 并告诉 AI 解压后的目录。网络、登录和系统权限需要你处理时，AI 应停在对应步骤说明原因。

如果 AI 没有本机操作能力，就照 [新手教程](quick-start.md) 执行命令；使用软件本身不需要 AI 常驻。
